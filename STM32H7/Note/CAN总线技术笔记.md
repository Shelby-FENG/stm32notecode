# 引言
	在电机控制领域中，常见的控制总线有PWM和串行RS_485。前者控制较为简单，适合精度比较低的场景，后者控制的带宽比较高，适合高动态的场景。除了这两个比较常见的控制总线外，还有一种工业上较为广泛应用的CAN总线，也就是我们今天所谈的主角，其智能且安全冗余的仲裁机制，使得其成为汽车电子和工业自动化领域的掌上明珠。

## 阶段认知

- 蓝色区域——CAN-FD arbitration phase / 仲裁阶段
	- 含义：这是通讯的"低速安全区域"。在这个区域内。总线上的所有节点（电机和主控）都必须遵守严格的基础限速。
	- 情境：收费站前的回流广场。所有车辆（报文）都在这里缓慢行驶，按喇叭（发送 ID），互相比对谁的优先级高（仲裁），ID 号大（优先级低）的车辆让行。同时，也是到达终点后，接收方盖章确认（ACK）的低速安全区。
- 绿色区域——Control field / 控制段
	- 含义：这是身份与权限的"交接区"。包含了一些列的标志位，决定了这帧报文接下来的命运。
	- 情境：收费站的闸机口。司机在这里向收费员递交文件，并申请"我要开启狂飙模式"（FD_CAN 模式）或者"我要拉超长的货物"（扩展帧）。
- 紫红区域——CAN-FD data phase / 数据阶段
	- 含义：不管 CAN 2.0 或 FDCAN 都是发送数据阶段，对于CAN-FD data phase，它区别于传统 CAN 的“高速区”。包含了真实的载荷数据（Data field）和校验码（CRC field）。
	- 情境：不限速的狂飙转线。一旦过了收费站闸机，且获批了加速权限，车队就会瞬间提速（1 Mbps—5 Mbps），极速运送且可以装载大量货物。
	Tip：传统 CAN 2.0 一般速度为 500 Kbps—1 Mbps
## 概念认知（FD_CAN Mode）

- SOF (Start of frame)：帧起始。标志着总线从空闲状态进入忙线，意味着"我要发车"。

- 11-bit identifier：它是车队的名字，也是优先级的象征。

- RTR（Remote transmission request）: 远程传输请求。相当于"遥控帧"标志位，所谓的遥控帧就是不装货物的车队，即主机发送一帧空数据来讨要从机的数据。

- IDE (Identifier Extension)：标识符扩展位。决定是用 11 位标准 ID 还是 29 位扩展 ID。
  
- BRS (Bit rate switching)：比特率切换。这是 FD_CAN 专属的"狂飙加速开关"。如果这位被置为 1（隐性电平），就意味着过了这个位之后，通信波特率将瞬间切换到高速挡。
  
- EDL (Extended data length)：扩展数据长度。这是 FD_CAN 专属的"加长货车许可证"。传统的 CAN 其标志位为 0（显性电平），FD_CAN 位 1（隐性电平），表示后面拉的数据可能超过 8 字节。
  
- ESI (Error state indicator)：错误状态指示。发送方用来告诉全网络自己的目前状态是否健康。如果它自己处于“被动错误”状态，这个标志位为 1。
  
- DLC (Data length code)：数据长度代码（4 bit）。运货清单，告诉接收方车厢里到底装了几个字节的货。
  
- Data field：数据段，传统 CAN 只能装 0—8 bytes，而 FD_CAN 的超级车厢可以装 0—64 bytes。
  
- CRC (Cyclic redundancy check)：循环冗余校验。安全封条。传统的 CAN 专用 15 bit CRC 校验码，而 FD_CAN 的数据量比较大，升级为更安全的 17 bit 或 21 bit 的 CRC。
  
- ACK (Acknowledge)：应答位。收件人确定签收的印章。
  
- EOF (End of frame)：结束帧（7 bit）。连续 7 个隐性电平位，表示车队已经驶出高速。
  
- IFS (Interframe space)：帧间空间（3 bit）。连续 3 个隐性电平位，强制规定“车队安全距离”，给主控时间去处理中断。
  
- DEL (Deliminator)：界定符。用来隔开不同功能的字段（如 CRC 界定符，ACK 界定符）。
  
- r0, r1：保留位。
  
## CAN 的一些重要机制

- **线与逻辑机制**：CAN 采用了一种叫*CSMA/CD+AMP(载波帧听多路访问、冲突检测+逐位仲裁)* 的机制，俗称 "线与逻辑"。
	在 CAN 总线上：
	- 逻辑 0 为"显性"电平（如一辆重型卡车）。
	- 逻辑 1 为“隐性”电平（如一辆自行车）。
	- 卡车和自行车同时上路，总线上表现为卡车，也就是 0（ 隐性电平）。
	  
- **自我监听机制**：CAN 采样一种回环线路，CAN 控制器的 TX 引脚连接着 RX 引脚，就像一个人自言自语。其中线与逻辑和自我监听机制的联合造就 CAN 的仲裁机制。
  
- **仲裁机制**：CAN 总线上的每个节点（主机和多个从机），在发送自己的 ID 的每一位时，都同时竖起耳朵监听总线，利用线与逻辑机制，仲裁每个节点的 ID 优先级。
	STM32 与 Motor 同时发送 ID 情境：
	- STM32_ID = 0000 0000 011，Motro_ID = 0000 0000 010。
	- 两者同时起步（SOF 发送），进入仲裁阶段：第 1 位到第 9 位，大家都发 0（显性），STM 32 发送 0，监听总线，读回 0，匹配！继续发送下一位，而电机发送 0，监听总线，读回 0，匹配！继续发送下一位。第 10 位，大家又都发 1（隐性），所以各自回读都是 1，直到第 11 位 STM 32 发送 1 而电机发送 0，1 和 0 相遇则呈现 0，所以电机读回 0 匹配，继续发送下一位，而 STM 32 发送 1 却读回 0，STM 32 的 FD_CAN 控制器（STM 32）认为有人的优先级比我高，我就向后排队了，在此次回合中变为只接收不发送，直到下一次仲裁在继续发送自己的 ID，综上所述，ID 小的优先级高。
	  
- **安全冗余机制**：若受到极端条件干扰数据，CRC 校验不过关，STM 32（主机）一旦发送 ACK 是 1（即被动错误），它会在下一个比特位节拍，立刻向总线发送连续 6 个显性电平 0（错误帧），这意味着想全网络节点广播："刚刚的那一帧数据报废，我没确认收到。"。此时 FD_CAN 控制器的错误计数器 TEC 的数值自增 8。只要总线上一空闲，STM 32 的 FD_CAN 控制器就重新发送刚才那一帧数据，如果 STM 32 一直发却没收到应答（ACK=1），TEC 自增大于255 时， FD_CAN 控制器认为自己的硬件坏了，不再向总线发送数据了，它会自动关闭发送功能，从总线上 Bus Off。 
 
## FD_CAN 通讯可视化

### 可视化情境
- 把主控STM32H7 想象成一个超级物流中心，把 64 字节的 MIT 控制参数（包含位置，速度，力矩等数据）发送给 GIM 6010-8 电机（从机）。
  
- *步骤 1*：驶入汇流广场（蓝色仲裁区域-低速区）
	- STM32 的 FD_CAN 控制器看到总线空闲，立刻发送一个显性电平 SOF，表示车队出库。
	- 紧接着，车队以较慢的基础波特率驶入蓝色区域（仲裁区域）。车牌写着它的 11-bit identifier（比如 0x008 的 MIT 指令）。此时如果其他电机也想发话，大家在这里比拼 ID（优先级），ID 小的车队，优先级越高，越能继续前进，其他的只能乖乖退回车库等待。
	- 补充：STM32 与 CAN 收发芯片是回环链路，也就是 MCU 的 RX 引脚会接到 TX 引脚的信号，实现自我监听。



### 实战

- 硬件：主机-STM32H723VGT6 (发送方)，板载 CAN 收发芯片（电平转换），从机-GIM 6010-8 关节电机 (接收方)。
  
- 软件：ST FD_CAN API (CubeMX 代码生成)。
